GETTING STARTED

Your guidebook, connected.

Glauco is a static app. Upload these files directly to GitHub Pages; there is no build step.

1. Connect a new Firebase project

  1. Create a new Firebase project on Spark and add a Web app. Copy its public configuration into config.js. Do not use Estuary’s project.
  2. Enable Authentication → Sign-in method → Google. Add your GitHub Pages hostname under Authentication → Settings → Authorized domains (hostname only, without the repository path).
  3. Create a Cloud Firestore Standard edition database in production mode. Keep the default database ID.
  4. Find both Google users in Authentication → Users and put their UIDs in config.js under ownerUids. If they do not exist yet, temporarily configure two distinct placeholder owner IDs that do not begin with REPLACE_, deploy, and have both owners attempt Google sign-in. They will be rejected by Glauco, but their Authentication records will appear. Copy their UIDs and then replace the placeholders.
  5. Paste the rules below into Firestore → Rules and replace both placeholder UIDs with the same two actual IDs from config.js. Publish the rules. No App Check, Cloudinary, or billing upgrade is required.
  6. Upload the contents of the ZIP to the root of your GitHub Pages repository. Select the branch and root folder in Settings → Pages. Open the HTTPS Pages URL and sign in.

The Firebase API key and UIDs are public identifiers. Firestore rules enforce access. Both owners use the same shared collection. Settings includes Google sign-out, which clears local guides and downloaded photos.

rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    function owner() {
      return request.auth != null
        && request.auth.token.firebase.sign_in_provider == 'google.com'
        && request.auth.uid in ['REPLACE_OWNER_1_UID', 'REPLACE_OWNER_2_UID'];
    }
    function validId(v) { return v is string && v.matches('^[a-zA-Z0-9][a-zA-Z0-9_-]{0,99}$'); }
    function short(v, n) { return v is string && v.size() <= n; }
    function imageUrl(v) {
      return short(v, 2000) && (v == '' || v.matches('^https://(upload\\.wikimedia\\.org|thumb\\.wikimedia\\.org|res\\.cloudinary\\.com)/.*'));
    }
    function validMeta(d, tripId) {
      return d.keys().hasOnly(['id','name','year','startDate','endDate','coverUrl','days','revision','archiveRevision','archived','updatedAt'])
        && d.keys().hasAll(['id','name','year','startDate','endDate','coverUrl','days','revision','archiveRevision','archived','updatedAt'])
        && d.id == tripId && validId(d.id) && short(d.name,180) && d.name.size() > 0
        && d.year is int && d.year >= 1900 && d.year <= 2200
        && d.startDate is string && d.startDate.matches('^[0-9]{4}-[0-9]{2}-[0-9]{2}$')
        && d.endDate is string && d.endDate.matches('^[0-9]{4}-[0-9]{2}-[0-9]{2}$')
        && d.endDate >= d.startDate && imageUrl(d.coverUrl)
        && d.days is list && d.days.size() > 0 && d.days.size() <= 120
        && validId(d.revision) && validId(d.archiveRevision)
        && d.archived is bool && d.updatedAt is number;
    }
    function validAttraction(d, attractionId) {
      return d.keys().hasOnly(['id','name','location','visitTime','summary','facts','sections','wikipediaUrl','sources','researchedAt','photos'])
        && d.keys().hasAll(['id','name','location','visitTime','summary','facts','sections','wikipediaUrl','sources','researchedAt','photos'])
        && d.id == attractionId && validId(d.id)
        && short(d.name,180) && d.name.size() > 0 && short(d.location,250) && short(d.visitTime,40)
        && d.summary is list && d.summary.size() > 0 && d.summary.size() <= 8
        && d.facts is list && d.facts.size() <= 15 && d.sections is list && d.sections.size() <= 15
        && short(d.wikipediaUrl,2000) && d.sources is list && d.sources.size() <= 15
        && short(d.researchedAt,10) && d.photos is list && d.photos.size() <= 12;
    }
    match /glauco/shared/trips/{tripId} {
      allow read: if owner();
      allow create, update: if owner() && validMeta(request.resource.data, tripId);
      allow delete: if false;
      match /versions/{revision}/attractions/{attractionId} {
        allow read: if owner();
        allow create: if owner() && validId(revision) && validAttraction(request.resource.data, attractionId);
        // An interrupted import may repeat an identical write; existing guides remain immutable.
        allow update: if owner() && request.resource.data == resource.data;
        allow delete: if false;
      }
    }
    match /{document=**} { allow read, write: if false; }
  }
}

2. Prepare an import file

Download the schema and attach it to ChatGPT with your Lambus export. The schema is the template for the trip file; it contains no trip data.

Download import schema

Use this prompt:

Create a Glauco trip file from the attached Lambus export, following the attached Glauco import-schema.json exactly.
Use ONLY the Daily Plan. Include temples, historic sites, museums, galleries, natural attractions, and substantive cultural visitor experiences. Exclude restaurants, shops, transport, flights, hotel rests, and internal reminders. Assess mixed shopping/workshop entries before including them. Omit days with no qualifying attractions.
Preserve full trip dates and infer the year only from the export's trip dates. Create a descriptive title for each day. Order days chronologically; order attractions by scheduled visit time when available, otherwise retain source order. Keep optional visitTime as a display string.
Write original, researched guide content: summary about 100–150 words in short paragraphs, plus about 300–600 additional words under helpful section headings. Scale detail to significance. Explain history, context, and specific things to notice on site. Use a few applicable key facts. Avoid invented stories or unverifiable claims. Distinguish tradition or disputed interpretations from established facts. Link to Wikipedia where an article exists and include supporting primary/authoritative sources. Record the research date. Practical information, if included, must be dated and verified.
Use 1–3 verified, suitably sized public Wikimedia photos per attraction, or [] when none is suitable. Use direct HTTPS image URLs from upload.wikimedia.org or thumb.wikimedia.org, with a small thumbnailUrl. Aim for 1200–1600px guide images and about 320px thumbnails. Verify the file's creator, source page, license and license URL. Do not invent image URLs or hotlink unrelated sites. coverUrl may use the first suitable attraction photo, or an empty string.
Use stable IDs containing only letters/numbers/hyphens/underscores, unique within their scope. If revising an earlier file, retain IDs. No HTML or Markdown in guide text; paragraphs are plain strings. No empty attraction days. Maximum 400 attractions and 5 MB guide metadata per trip; maximum 12 MB per file.
Return a downloadable UTF-8 JSON file with format "glauco-trip-file", version 1, and trips. Do not insert it into app files or include private notes from unrelated export sections.

In Glauco, choose Import, select the prepared JSON file, and review its counts. For duplicates choose Import as new or Replace existing. Replacement preserves archive status. The JSON file is your source copy; Glauco does not export backups or edit guide content.

3. Take it offline

Open a trip and choose Download. Keep Glauco open until it reports Offline ready. Downloads include the guide text, cover, thumbnails, and full guide photos. Settings shows the saved payload size and lets you update or remove each download. Size excludes browser database and cache overhead.

The first Google sign-in requires connectivity. Later you can reopen downloaded guides while offline using the saved authorized session. External Wikipedia and source links require internet access. No Google account credentials are stored by Glauco.

Photos must allow cross-origin downloads. A failed or interrupted download is never marked complete; an older successful download stays available during an update. For a blocked image, prepare a revised trip file with a supported Wikimedia URL. Images must be raster images, no larger than 8 MB each, with at most 300 MB of photos per trip.

Offline downloads belong to each browser or installed app. Browsers can remove stored data under storage pressure; Glauco requests persistent storage after downloading. Save your original import file and check Offline ready before travel.

Install on Android through the in-app Install prompt or Chrome’s Add to Home screen. On iPhone, use Safari → Share → Add to Home Screen. The layout includes safe-area padding and bottom navigation.

Updates and synchronization

Imported content saves locally first and syncs when online. Imports upload a new immutable guide version, then switch the trip to it atomically. Archive and restore also sync. If the same trip changes on another device before a pending change syncs, Settings asks you to use the synced version; re-import the original file if needed.

Old guide versions remain in Firestore so interrupted imports and older devices can read safely. For two people this is small; old versions can be removed manually in the Firebase console after all devices have synced.

Before publishing future code releases, increment the same version in sw.js, release.json, app.js, the release meta and asset URLs in index.html, and manifest.webmanifest. The app checks while online and offers Update. It avoids reloading during a dialog, download, or unsynced change.

Changing config.js alone is fetched fresh on the next online reload. When changing image hosts, also update the CSP in index.html, the allowlist in sw.js, and the Firestore rules. HTTPS only; public image URLs are required.
